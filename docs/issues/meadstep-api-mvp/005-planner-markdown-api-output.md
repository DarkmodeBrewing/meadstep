## What to build

Once `@meadstep/core` owns Markdown generation for the complete planner result, include that same generated Markdown in the planner API response. The API should not create a separate export formula or endpoint that can drift from the structured result.

## Acceptance criteria

- [ ] `POST /api/v1/planner/honey-only` includes `data.markdown` once the planner result supports complete brew-plan Markdown.
- [ ] The Markdown string is generated by `@meadstep/core` from the same structured planner result returned in `data`.
- [ ] Standalone tool endpoints do not include Markdown output.
- [ ] The planner API service reuses one calculation/export path rather than recalculating separately for Markdown.
- [ ] `docs/api/openapi-v1.yaml` documents `data.markdown` on the planner response.
- [ ] Tests cover Markdown presence, source consistency with structured planner result, selected-unit wording where applicable, and no Markdown on standalone tool endpoints.
